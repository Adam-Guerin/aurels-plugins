## Changes in this working tree

The validation workflow previously ran the OpenClaw package test before installing the runtime required by its real hook-runner E2E, so CI would fail with a missing `OPENCLAW_PACKAGE_ROOT`. The runtime installation now precedes the package tests and its path is passed to that step. The exact package test/check sequence passes locally against the isolated OpenClaw 2026.3.28 package.

The current integration-package checks pass seven SDK-level tests: LangGraph allow/block/rewrite via real ToolNode dispatch, OpenAI Agents allow/rewrite through invokeFunctionTool plus block through the SDK's tool-guardrail runner, and stable/content-bound idempotency through the shared SDK. In an isolated temporary Python environment, CrewAI 1.15.22's actual `BaseTool.run()` was exercised with synthetic decisions: allow reached `_run`, while block did not. This exposed and fixed missing Pydantic v2 private model state in the wrapped tool. The 33 CrewAI unit tests also pass after the fix.

The current SDK fixtures used for adapter contract checks are LangGraph 1.4.18, LangChain Core 1.2.13, and OpenAI Agents 0.18.0. Actual LangGraph ToolNode dispatch and OpenAI Agents invocation/guardrail runners were exercised with synthetic actions. No model provider was called. These results validate adapter seams only, not full agent turns or production support.

Current SDK execution tests initially failed and exposed API drift: LangGraph's ToolNode passes a ToolCall envelope, and OpenAI Agents 0.18 invokes function tools through invoke(runContext, input, details) and expects tool guardrails with a run method and nested behavior result. Both adapters now preserve the LangGraph call ID and evaluate only its actual arguments; OpenAI's wrapper and guardrail now conform to the installed SDK. Strict TypeScript checks and SDK-owned dispatch helpers pass. CI installs the package-lock-pinned test dependencies on both validation and release workflows.

It also blocks if an unexpected error escapes the complete pre-tool evaluation path and reports host-declared tool failures as failure telemetry.

## Remaining security and product gaps

### P1 — Approval must cover the final dispatched arguments

The ordinary lower-priority hook rewrite gap is mitigated using OpenClaw's approval snapshot contract: Aurels runs first, returns the parameters it evaluated, and requires one-shot approval even after a remote `allow`. Still validate this through a live tool dispatch and approval resolution on the supported runtime. The guarantee excludes host-trusted policy layers that execute before ordinary hooks, native paths with narrower approval semantics, and tools that bypass these hooks entirely.

Hermes has a separate unresolved final-arguments boundary. Inspection of the installed host's `PluginManager.invoke_hook` and sequential/concurrent tool dispatchers confirms callbacks receive the same mutable argument mapping in order, and dispatch uses the mapping after callbacks finish. The native hook can block but cannot replace/freeze the final arguments or attach a payload-bound permit checked at dispatch. Thus a later Hermes plugin may mutate arguments after Aurels returns `allow`; the plugin cannot close this gap by snapshotting locally. Until Hermes offers an immutable final invocation context or a verification hook adjacent to dispatch, only use native-hook allow for consequential tools when hook ordering and the absence of later mutators are controlled. A trusted custom adapter may check and execute the same canonical snapshot as an interim mitigation.

### P1 — Authorization permits are not standardized across integrations

OpenClaw, Hermes, and most other adapters currently act on an authenticated API `allow` decision; they do not locally verify a signed, expiring authorization bound to the canonical arguments and final invocation. The experimental MCP proxy is the exception in flow shape: its opt-in path obtains an execution permit and consumes it through the backend before forwarding, but this server-side check is not a shared cross-plugin permit contract or local signature verification. A product-level permit contract should bind invocation ID, canonical action digest, audience/host, policy version, expiry, and one-time nonce, then be checked at the host's final dispatch boundary with replay protection and key rotation. That requires backend support and host final-invocation APIs; merely adding signature verification inside adapters cannot prevent a later host hook from changing the dispatched arguments.

### P1 — No full OpenClaw agent/approval-resolution end-to-end

The normal installed OpenClaw 2026.3.2 remains older than the declared 2026.3.28 minimum. The hook-runner contract has now been exercised against the actual 2026.3.28 minimum and current 2026.9.6 package, and confirms the exact-parameter snapshot/approval contract; 2026.3.2 remains fail-closed. This still does not start a Gateway or agent, invoke a live tool wrapper, or resolve approval through the configured approval surface. One-shot approval/denial, timeout, cancellation, and no-route therefore remain unverified end to end.

### P1 — Retrospective is not enforcement and cannot prove task success

Hermes retrospective mode intentionally allows execution before review. The lifecycle callback receives action summaries but not the user's complete goal or tool results, so the model can point out apparent risk but cannot reliably decide whether the agent accomplished its task or respected intent. Do not market it as an authorization or safety boundary. The installed OpenClaw `PluginRuntimeCore` exposes no host-owned model invocation facade; adding parity requires an officially supported, bounded plugin API for calling the configured agent provider and attributing provider/model usage. Do not reach into private runner internals or extract provider credentials as a substitute.

### P2 — Model-data handling and live quality

The review is redacted and bounded. Core OpenClaw, Hermes, and migrated TypeScript, Claude Code, Codex, MCP, and CrewAI redactors detect common embedded credential formats (Bearer, OpenAI-style `sk-…`, AWS key IDs, GitHub tokens, and JWTs) in ordinary fields such as `content`, `message`, and `payload`. A shared synthetic corpus now checks OpenClaw, Hermes, CrewAI, and shared TypeScript for parity; tests also cover CrewAI unit telemetry and actual Claude/Codex/MCP telemetry requests. This remains heuristic redaction, not DLP: it cannot guarantee removal of personal, confidential, novel, split, or encoded secrets. Patterns remain duplicated between language-specific/standalone packages and can drift; next extend the corpus through each adapter's actual telemetry boundary and make it a release gate, then consider local feature extraction and configurable redaction policies. With OpenAI or another hosted Hermes provider, summaries leave the machine under that provider's normal terms/quota. Exercise the real configured model only with synthetic data, inspect the resulting log, measure latency/cost, and decide whether argument capture should be disabled or further minimized by default.

### P2 — Durable audit delivery and crash behavior

Default remote telemetry remains best-effort. Both OpenClaw and Hermes now offer an opt-in bounded local outbox (`AURELS_TELEMETRY_DURABLE=true`) that persists redacted events before returning from the relevant hook, retries on startup, later events, and a capped 1-to-60-second exponential schedule, and removes them after successful ingestion. Abandoned staging files older than 24 hours are pruned during queue maintenance. The Aurels API upserts by canonical event hash, so retrying an identical event is deduplicated. This is process-restart recovery, not a transaction with tool execution or an absolute disk-durability guarantee: full/unavailable storage, device loss, and filesystem failure can still lose events. The plaintext spool is heuristically redacted, capped at 1,000 events / 8 MiB / 64 KiB per event, and expires events after seven days; enabling it is an explicit local data-retention choice.

Windows Hermes testing exposed a real cross-thread lock-release failure: unlinking `.enqueue.lock` could raise `WinError 32` while another contender briefly read it, after which all writers timed out and zero events were persisted. The outbox now retries that specific Windows sharing violation for up to 500 ms; the strengthened 16-thread queue-cap test requires at least one persisted event, verifies successful writes correspond to files, and still enforces the byte cap. A further race was found in stale-lock inspection: a lock that disappears after `FileExistsError` must be treated as released, not stale-and-safe-to-unlink, since a new writer may already have recreated that path. Hermes now retries instead of deleting in this case, and a direct regression test confirms the missing-path classification. The queue-contention rerun after this last change was interrupted and remains unverified. The MCP proxy also now tracks outstanding telemetry and waits for it before exiting when its upstream process exits; a dispatch E2E verifies redacted telemetry reaches the local API harness before shutdown. Forced termination, machine loss, and shutdown timeout still prevent a durability guarantee.

### P2 — Validation coverage

The five-case Hermes dispatcher E2E passes on this PC using the locally installed 0.15.1 host executor and a deterministic fake Aurels decision client. It does not contact a live Aurels server or exercise real policy/model behavior. The workflow's updated host pin must still be validated in CI; modern Hermes native approval resolution is not yet exercised locally. There is no full OpenClaw agent/approval-resolution E2E. Its installed-package runner test checks the actual public hook runner's merge contract, not tool dispatch or live UI approval.

## Verdict

The plugins are installable and their core hook paths are testable locally. OpenClaw now requires one-shot user confirmation for a remote allow so lower-priority plugins cannot change the evaluated parameters; this tightens integrity at the cost of an approval prompt on every allowed call. Hermes has a useful no-Aurels-key retrospective mode backed by its host-configured model, but this is advisory and may still use a cloud provider. The package is **not yet evidence of a production-complete security boundary**: full supported-host dispatch/approval E2E, trusted-policy/native-path boundaries, durable audit guarantees, and live retrospective quality remain open.

OpenClaw's current hook contract and plugin approvals are documented in the [tool-policy hook reference](https://docs.openclaw.ai/plugins/hooks/tool-policy) and [plugin permission request guide](https://docs.openclaw.ai/plugins/plugin-permission-requests).
